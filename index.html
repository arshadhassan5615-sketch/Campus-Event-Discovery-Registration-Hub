    One list, not five

    Event notices on campus live in WhatsApp groups, notice boards and separate club pages. CampusHub collects them in a single searchable list with filters for category and status.

Problem statement & objectives

CA1 · Problem-statement based project

The problem

Campus events are announced across scattered channels — WhatsApp groups, notice boards, department emails and club pages. Students miss events they would have attended, and organizers have no reliable way to know how many people are coming. Registration is manual, duplicate entries are common, and nobody can say at a glance whether a room still has space.

Our objectives

  • One searchable catalogue of every campus event.
  • Live seat availability that cannot be overbooked.
  • Fast registration with duplicate-ID prevention.
  • A dashboard an organizer can read in five seconds.
  • A responsive interface that works on a phone.

Outcomes

  • Events are discoverable by category, status and keyword.
  • Capacity limits hold under repeated registration attempts.
  • Cancellations are logged with a status, not erased.
  • Validated input and escaped output throughout.
  • Works offline after first load — no backend required.

Technologies

  • HTML5 Semantic structure, accessible forms
  • CSS3 Grid, custom properties, media queries
  • JavaScript DOM, validation, state, localStorage
  • Git & GitHub Version control and source hosting
  • GitHub Pages Public deployment

About CampusHub

A responsive campus event discovery and registration hub for workshops, competitions, talks and club events. Built as the CA1 problem-statement project for CSE 326.

Problem in one line

Campus events are scattered across WhatsApp groups, notice boards and club pages, so students miss them and organizers cannot track seats.

What the app does

Lists every event in one place, shows live seat availability, prevents overbooking and duplicate registrations, and records cancellations instead of deleting them.

Technologies used

HTML5 for structure, CSS3 Grid and media queries for the responsive layout, and vanilla JavaScript for state, validation and localStorage persistence. Hosted on GitHub Pages.
